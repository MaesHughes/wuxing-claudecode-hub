**版本:** v1.0
**创建时间:** 2025-01-22

## 一、核心问题分析

### 1.1 当前定位的问题

通过讨论，我们发现当前定位存在以下问题：

| 问题点 | 说明 | 影响 |
|--------|------|------|
| **Hooks 不需要"管理"** | Hooks 是配置脚本，不是独立包 | 功能定位偏差 |
| **本地市场局限** | 只能管理本地 skills/commands 文件夹 | 无法获取社区资源 |
| **缺乏开放性** | 没有让开发者提交扩展的机制 | 生态无法扩展 |

### 1.2 项目真正的价值主张

**本质问题:** Claude Code 生态缺乏一个统一的"扩展市场"

- 官方没有提供中心化的扩展发现和安装机制
- 优秀的开源扩展散落在 GitHub 各处
- 用户难以发现和安装这些扩展
- 开发者难以分发自己的扩展

**我们的使命:** 成为 Claude Code 的"插件市场"

## 三、功能重新规划

### 3.1 优先级调整

#### 🔴 P0 - 核心功能（必须）

| 功能 | 描述 | 价值 |
|------|------|------|
| **在线扩展索引** | 从远程仓库获取扩展列表 | 核心差异化 |
| **GitHub 集成** | 直接从 GitHub 安装扩展 | 降低分发门槛 |
| **扩展详情页** | 显示 README、评分、安装数 | 帮助用户决策 |
| **一键安装** | 从远程直接安装到本地 | 核心使用体验 |
| **已安装管理** | 查看、更新、卸载已安装扩展 | 基础管理功能 |

#### 🟡 P1 - 重要功能（尽快）

| 功能 | 描述 | 价值 |
|------|------|------|
| **评分评论系统** | 用户可以评分和评论 | 质量信号 |
| **搜索和过滤** | 按名称、类别、标签搜索 | 提升发现效率 |
| **版本管理** | 支持多版本安装和升级 | 生产可用性 |
| **依赖处理** | 自动处理扩展依赖 | 降低使用复杂度 |
| **使用统计** | 显示安装数、下载量 | 质量信号 |

#### 🟢 P2 - 增值功能（后续）

| 功能 | 描述 | 价值 |
|------|------|------|
| **开发者提交系统** | 允许开发者提交自己的扩展 | 生态扩展 |
| **自动化测试** | 自动测试扩展兼容性 | 质量保证 |
| **推荐引擎** | 基于使用情况推荐扩展 | 提升发现效率 |
| **云同步** | 跨设备同步已安装扩展 | 用户体验 |
| **团队协作** | 团队共享扩展配置 | 企业功能 |

### 3.2 Hooks 的新定位

**Hooks 从"管理"转为"文档模板"：**

| 原定位 | 新定位 |
|--------|--------|
| Hooks 管理功能 | Hooks 配置模板库 |
| 安装/卸载 Hooks | 浏览和复制 Hooks 配置 |
| 独立管理界面 | 集成到文档/示例页面 |

**实现方式：**
- 在扩展详情页展示 Hooks 配置示例
- 提供常见 Hooks 模板的文档
- 用户可以复制配置到自己的 settings.json

### 4.2 扩展索引设计

#### 方案 A: GitHub 优先（推荐 MVP）

**优点：**
- 无需维护后端数据库
- 开发者直接在 GitHub 维护扩展
- 降低我们运维成本

**实现：**
```
扩展索引 = GitHub 仓库列表
├── 官方维护的精选列表
└── 社区提交的 PR (类似 awesome-lists)
```

#### 方案 B: 自建注册表（长期）

**优点：**
- 更丰富的元数据
- 更好的搜索和推荐
- 可以存储评分、评论等

**实现：**
```
扩展注册表
├── 扩展元数据 (名称、描述、分类)
├── 版本信息
├── 评分评论
└── 使用统计
```

### 4.3 GitHub 集成方案

#### 扩展发现（从 GitHub）

```javascript
// 扫描 GitHub 上的 Claude Code 扩展
const discoverExtensions = async () => {
  // 1. 搜索包含特定标签的仓库
  const repos = await githubAPI.search.repos({
    q: 'topic:claude-code-skill OR topic:claude-code-command',
    sort: 'stars',
    order: 'desc'
  });

  // 2. 解析仓库元数据
  const extensions = repos.map(repo => ({
    id: repo.full_name,
    name: repo.name,
    description: repo.description,
    stars: repo.stargazers_count,
    homepage: repo.homepage_url,
    // 从 README/manifest 读取详细信息
    metadata: await parseRepoMetadata(repo)
  }));

  return extensions;
};
```

#### 从 GitHub 安装

```javascript
// 直接从 GitHub 安装扩展
const installFromGitHub = async (repoUrl, type) => {
  // 1. 克隆/下载仓库
  const tempDir = await downloadRepo(repoUrl);

  // 2. 验证扩展结构
  const manifest = await validateExtension(tempDir, type);

  // 3. 复制到目标目录
  const targetDir = getInstallPath(type, manifest.name);
  await fs.copy(tempDir, targetDir);

  // 4. 清理
  await fs.remove(tempDir);

  return { success: true, path: targetDir };
};
```

#### Manifest 验证

```javascript
// 验证扩展清单
const validateManifest = (manifest) => {
  const required = ['name', 'version', 'type', 'description'];
  const types = ['skill', 'command', 'mcp-server'];

  // 必填字段
  for (const field of required) {
    if (!manifest[field]) {
      throw new Error(`Missing required field: ${field}`);
    }
  }

  // 类型验证
  if (!types.includes(manifest.type)) {
    throw new Error(`Invalid type: ${manifest.type}`);
  }

  // Claude 兼容性
  if (manifest.claude?.minVersion) {
    // 检查版本兼容性
  }

  return { valid: true };
};
```

## 八、风险管理

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| GitHub API 限流 | 发现功能受限 | 实现缓存机制 |
| 扩展兼容性 | 安装失败 | 严格验证 + 沙盒测试 |

### 8.2 社区风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 恶意扩展 | 用户安全问题 | 代码审查 + 声誉系统 |
| 低质量扩展 | 市场混乱 | 评分系统 + 精选列表 |
| 维护成本 | 运营压力大 | 自动化 + 社区自治 |
